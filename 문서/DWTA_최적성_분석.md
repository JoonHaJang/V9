## 1. 기초 개념 정리

### 1.1 정수 계획법 (Integer Program, IP)

**쉬운 설명:** "결정을 0 또는 1(혹은 정수)로만 할 수 있는 최적화 문제"입니다.
예: "이 포대를 이 위협에 할당할까요? 네(1) 또는 아니오(0)."

수식으로 쓰면:

$$\min\ c^T x \quad \text{s.t.}\ Ax \leq b,\ x \geq 0,\ \mathbf{x \in \mathbb{Z}^n}$$

- $c$: 각 결정의 비용(또는 이득)
- $A, b$: 제약 조건
- $x \in \mathbb{Z}^n$: **모든 변수가 정수여야 함** ← 이게 핵심 제약

> **왜 어려운가?**
> 정수 조건($x \in \mathbb{Z}^n$) 때문입니다. 연속적으로 움직일 수 없어서 탐색 공간이 폭발적으로 커집니다.
> 일반적인 IP는 **NP-hard** — 변수가 많아질수록 계산 시간이 지수적으로 증가합니다.

---

### 1.2 LP 완화 (LP Relaxation)

**쉬운 설명:** IP에서 "정수여야 한다"는 규칙을 없애고 소수도 허용하는 것입니다.

$$\min\ c^T x \quad \text{s.t.}\ Ax \leq b,\ x \geq 0,\ \mathbf{x \in \mathbb{R}^n}$$

- $x \in \{0,1\}$ 대신 $x \in [0,1]$ 허용
- 예: $x_{ij} = 0.7$ ("이 포대를 이 위협에 70% 할당") 같은 값도 가능

**LP(선형 계획법)는 다항 시간에 풀 수 있습니다.** IP보다 훨씬 빠릅니다.

> **핵심 아이디어:**
> LP 완화의 feasible set(가능한 해의 집합) ⊇ IP의 feasible set
> 따라서 LP 완화의 최적값 ≤ IP의 최적값 (최소화 문제 기준)
>
> 만약 LP 완화를 풀었더니 **이미 정수해가 나온다면**, 비싼 IP를 따로 풀 필요가 없습니다!

## 2. 우리 문제 정식화

단일 최적화 윈도우(5초 구간)에서의 할당 문제를 정확히 씁니다.
여기서 $k_{ij}$는 고정된 파라미터로 취급합니다(이유는 6절에서 설명).

$$\min_{x} \quad -\sum_{i \in \mathcal{B}} \sum_{j \in \mathcal{T}} c_{ij}\, x_{ij}$$

**변수 설명:**
- $x_{ij} \in \{0,1\}$: 포대 $i$를 위협 $j$에 할당하면 1, 아니면 0
- $c_{ij} = v_j \cdot k_{ij} \cdot P_j$: 할당의 가치 (자산가치 × K인자 × 요격확률)
- $\mathcal{B}$: 전체 포대 집합, $\mathcal{T}$: 전체 위협 집합

**제약 조건:**

$$\sum_{j \in \mathcal{T}} x_{ij} \leq C_i \quad \forall i \in \mathcal{B} \tag{제약1: 포대 동시 교전 한도}$$

$$\sum_{i \in \mathcal{B}^U} x_{ij} \leq 1 \quad \forall j \in \mathcal{T} \tag{제약2: 위협당 LSAM 최대 1개}$$

$$\sum_{i \in \mathcal{B}^L} x_{ij} \leq 1 \quad \forall j \in \mathcal{T} \tag{제약3: 위협당 MSAM 최대 1개}$$

- $C_i = 6$: 포대당 동시 교전 가능 수
- $\mathcal{B}^U$: LSAM 포대 집합 (상층)
- $\mathcal{B}^L$: MSAM 포대 집합 (하층)

> **직관적 해석:**
> "위협을 가장 많이 요격하도록 포대를 배정하되, 각 포대는 동시에 $C_i$개까지만,
> 각 위협은 LSAM 1개 + MSAM 1개까지만 담당 가능."

## 3. 총 단모듈성 (TU)

이 절이 증명의 핵심입니다. 용어를 하나씩 정의합니다.

### 3.1 행렬식 (Determinant)

**쉬운 설명:** 정방행렬(행 수 = 열 수인 행렬)에 하나의 숫자를 대응시키는 함수입니다.
행렬이 "뒤집을 수 있는지(역행렬 존재)" 여부를 알려줍니다.

$$\det\begin{pmatrix} a & b \\ c & d \end{pmatrix} = ad - bc$$

### 3.2 부분행렬 (Submatrix)

**쉬운 설명:** 행렬에서 일부 행과 열만 골라서 만든 작은 행렬입니다.

$$A = \begin{pmatrix} 1 & 0 & 1 \\ 0 & 1 & 1 \\ 1 & 1 & 0 \end{pmatrix}
\quad \Rightarrow \quad
\text{1,3행 + 1,2열 선택} \Rightarrow B = \begin{pmatrix} 1 & 0 \\ 1 & 1 \end{pmatrix}$$

**정사각 부분행렬**: 행 수 = 열 수인 부분행렬.

### 3.3 총 단모듈 행렬 (Totally Unimodular Matrix, TU)

> **정의:** 행렬 $A$가 TU이다 ⟺ **모든 정사각 부분행렬 $B$의 행렬식이 $-1$, $0$, $+1$ 중 하나다.**

$$\forall \text{ 정사각 부분행렬 } B \subseteq A: \quad \det(B) \in \{-1,\ 0,\ +1\}$$

**왜 이게 중요한가?** 다음 정리 때문입니다.

### 3.4 Hoffman-Kruskal 정리 (1956)

> **정리:** $A$가 TU이고 $b$의 모든 원소가 정수이면,
> LP $\{x \in \mathbb{R}^n \mid Ax \leq b,\ x \geq 0\}$의 **모든 꼭짓점(optimal vertex)은 정수이다.**

**왜 꼭짓점이 중요한가?**
LP의 기본 정리에 의해, LP의 최적해는 반드시 feasible polytope(가능한 해들이 이루는 볼록 다면체)의 **꼭짓점에서 달성**됩니다.

```
    가능한 해 집합 (다각형)
         *-----*
        /       \
       *    ★    *    ← LP 최적해는 반드시 꼭짓점(*)에서 달성
        \       /
         *-----*
```

따라서: **$A$가 TU** → 모든 꼭짓점이 정수 → LP 최적해가 정수 → **IP를 LP로 풀 수 있음!**

## 4. 네트워크 흐름으로 표현하기

우리 제약 행렬이 TU임을 보이기 위해, 문제를 **네트워크 흐름(Network Flow)** 으로 표현합니다.

### 4.1 노드-호 발생 행렬 (Node-Arc Incidence Matrix)

**쉬운 설명:** 그래프에서 "어떤 노드가 어떤 간선에 연결되어 있는가"를 나타내는 행렬입니다.

$$M_{ve} = \begin{cases} +1 & \text{간선 } e \text{가 노드 } v \text{에서 출발} \\ -1 & \text{간선 } e \text{가 노드 } v \text{로 도착} \\ 0 & \text{무관} \end{cases}$$

예시:
```
노드 A --간선1--> 노드 B --간선2--> 노드 C

       간선1  간선2
  A  [  +1     0  ]
  B  [  -1    +1  ]
  C  [   0    -1  ]
```

### 4.2 우리 문제를 그래프로

```
소스(s)
  │ 용량 C_i
  ▼
포대 노드(b_i)  ─── x_ij(용량 1) ───▶  위협-LSAM 노드(t_j^U) ──▶ 싱크(r)
                                   ──▶  위협-MSAM 노드(t_j^L) ──▶ 싱크(r)
```

**노드 종류:**
- $s$: 소스(source) — 자원이 시작되는 곳
- $b_i$: 포대 $i$를 나타내는 노드
- $t_j^U$: 위협 $j$에 대한 LSAM 교전 노드
- $t_j^L$: 위협 $j$에 대한 MSAM 교전 노드
- $r$: 싱크(sink) — 자원이 흡수되는 곳

**간선의 의미:**
- $(s \to b_i)$: 포대 $i$의 총 교전 능력, 용량 $C_i$
- $(b_i \to t_j^U)$: LSAM 포대 $i$를 위협 $j$에 할당 = $x_{ij}$, 용량 1
- $(t_j^U \to r)$: 위협 $j$에 LSAM 1개까지, 용량 1

우리의 제약 조건이 그대로 네트워크의 **유량 보존 법칙**으로 표현됩니다.

## 5. 핵심 증명: LP 완화 = 정수해

### 보조 정리: 방향 그래프의 노드-호 발생 행렬은 TU이다

**증명 (수학적 귀납법):**
임의의 $k \times k$ 정사각 부분행렬 $B$에 대해 $\det(B) \in \{-1, 0, +1\}$을 증명합니다.

**기저 단계 ($k=1$):**
$M$의 각 원소는 $\{-1, 0, +1\}$이므로 자명하게 성립. ✓

**귀납 단계:** $k-1$ 이하에서 성립한다고 가정하고 $k$에 대해 증명합니다.

임의의 $k \times k$ 부분행렬 $B$를 선택합니다.
$B$의 열 = 그래프의 간선들, 행 = 그래프의 노드들에 해당합니다.

**[경우 1]** 어떤 열이 **전부 0**이면:
$$\det(B) = 0 \quad \checkmark$$

**[경우 2]** 어떤 열에 **원소가 정확히 1개** 있으면:
그 열을 따라 코팩터(cofactor) 전개:
$$\det(B) = \underbrace{(\pm 1)}_{\text{하나뿐인 원소}} \cdot \det(B')$$
$B'$는 $(k-1) \times (k-1)$ 부분행렬 → 귀납 가정에 의해 $\det(B') \in \{-1,0,+1\}$
따라서 $\det(B) \in \{-1, 0, +1\}$. ✓

**[경우 3]** 모든 열에 **원소가 정확히 2개** 있으면:
방향 그래프의 각 간선은 정확히 한 노드에서 출발(+1)하고 한 노드에 도착(-1)합니다.
따라서 각 열의 합:
$$\sum_{\text{모든 행 } v} B_{ve} = (+1) + (-1) = 0 \quad \forall \text{ 열 } e$$
모든 열의 행 합이 0 → **행들이 선형 종속** → $\det(B) = 0$. ✓

세 경우 모두 $\det(B) \in \{-1, 0, +1\}$. **∎**

---

### 주정리: 우리 LP 완화는 항상 정수해를 가진다

**제약 행렬 $A'$ 구성:**
소스 행과 싱크 행을 제거한 행렬 $A'$를 보면:

| | $x_{ij}$ (포대$i$ → 위협$j$ 할당) |
|---|---|
| 포대 $i$ 행 | $+1$ (출발 노드) |
| 위협 $j$ 층 행 | $+1$ (도착 노드, 방향 반전 후) |
| 나머지 | $0$ |

각 열에 $+1$이 정확히 2개 → 방향 그래프 발생 행렬의 구조와 동일 → **$A'$는 TU**.

**증명:**

1. $A'$는 TU (방금 증명)
2. $b = (C_i, 1, 1, \ldots)^T$ — 모든 원소가 양의 정수
3. Hoffman-Kruskal 정리 → feasible polytope의 모든 꼭짓점이 정수
4. LP 최적해는 꼭짓점에서 달성
5. 따라서 LP 최적해 $x^* \in \{0, 1\}^{|\mathcal{B}||\mathcal{T}|}$ **∎**

> **한 줄 요약:**
> 우리 할당 문제는 LP로 풀어도 자동으로 0 또는 1만 나옵니다.
> Branch & Bound(분기한정법) 없이도 이론상 전역 최적해를 찾을 수 있습니다.

## 6. McCormick이 있어도 괜찮은가?

실제 코드에서 $k_{ij}$는 고정 파라미터가 아니라 **연속 변수** `k_var`로 구현되어 있습니다.
McCormick 선형화를 통해 $w_{ij} = x_{ij} \cdot k_{\text{var}} \cdot P_j$를 4개의 선형 제약으로 표현합니다:

```python
# 코드의 실제 McCormick 제약
w ≥ kP_tight_min × x          # 하한 1
w ≥ k_var × P - kP_max × (1-x)  # 하한 2
w ≤ kP_tight_max × x           # 상한 1
w ≤ k_var × P                  # 상한 2
```

**TU가 깨질 수 있는가?**
$k_{\text{var}}$가 진짜 자유 변수라면 McCormick 제약이 추가되어 TU가 깨질 수 있습니다.

**그러나 실제로는 문제없습니다:**

목적함수 $\min -\sum v \cdot w_{ij}$를 최소화하려면 $w_{ij}$를 최대한 크게 해야 합니다.
상한 제약 $w_{ij} \leq k_{\text{var}} \cdot P$가 있으므로, solver는 **$k_{\text{var}} = k_{\text{tight\_max}}$로 수렴**합니다.

$$k_{\text{tight\_max}} = k_{\text{actual}} \times 1.05 \approx k_{\text{actual}} \quad \text{(거의 상수)}$$

결과적으로 $k_{\text{var}}$는 실질적으로 상수처럼 동작 → **TU 성질 복원**.

| 상황 | TU 여부 | 설명 |
|------|---------|------|
| $k$가 진짜 자유 변수 | ❌ 깨짐 | McCormick coupling 때문 |
| $k$가 상수 파라미터 | ✅ 성립 | 네트워크 구조 그대로 |
| **우리 경우 (±5% 범위)** | **✅ 실질적으로 성립** | solver가 상한으로 수렴 |

## 7. 롤링 호라이즌의 한계

앞에서 단일 윈도우 안에서는 최적임을 증명했습니다.
그런데 우리 시뮬레이션은 5초마다 **반복해서** 윈도우를 푸는 방식입니다.
이것을 **롤링 호라이즌(Rolling Horizon)** 이라고 합니다.

### 7.1 진짜 최적 문제 vs. 우리가 푸는 문제

**진짜 최적 문제 (전체 지평선, Full-Horizon):**

$$\text{(FH-DWTA)} \quad \min_{x} \quad -\sum_{t=1}^{N} \sum_{i,j} c_{ij}^t\, x_{ij}^t$$

$$\text{s.t.} \quad \underbrace{\sum_{j} x_{ij}^t \leq C_i}_{\text{동시 교전 제약}} \quad \forall i, t$$

$$\quad \underbrace{\sum_{t=1}^{N} \sum_{j} 2 \cdot x_{ij}^t \leq M_i}_{\text{총 탄약 제약}} \quad \forall i$$

**우리가 푸는 문제 (롤링 호라이즌, 매 시간 $t$마다):**

$$\text{(RH-DWTA}_t\text{)} \quad \min_{x^t} \quad -\sum_{i,j} c_{ij}^t\, x_{ij}^t$$

$$\text{s.t.} \quad \sum_{j} x_{ij}^t \leq C_i \quad \forall i$$

두 문제의 차이: **총 탄약 제약이 없습니다!**

> 롤링 호라이즌은 "지금 이 순간"만 보고 결정합니다.
> "나중에 탄약이 부족해질 수 있다"는 것을 전혀 고려하지 않습니다.

### 7.2 구체적 반례: 롤링 호라이즌이 형편없는 해를 낼 수 있다

**설정:**
- LSAM 포대 1개, 동시 교전 1개, 총 탄약 **살보 1회** (2발)
- 위협 2개가 순서대로 도달:
  - $t=1$: 위협 A (가치 $v_A = 5$, 요격확률 $P=1.0$)
  - $t=2$: 위협 B (가치 $v_B = 100$, 요격확률 $P=1.0$)

**롤링 호라이즌의 결정:**
```
t=1: A가 보임, v_A=5 > 0 → 할당! → 탄약 소진
t=2: B가 보임, 탄약 없음 → 포기
-------------------------------------
롤링 호라이즌 총 이득 = 5
```

**전체 지평선 최적해:**
```
t=1: A 무시 (탄약 아끼기)
t=2: B 요격! → 이득 100
-------------------------------------
전체 지평선 총 이득 = 100
```

**근사비 (Approximation Ratio):**

$$\rho = \frac{\text{전체 지평선 최적값}}{\text{롤링 호라이즌 달성값}} = \frac{100}{5} = 20$$

롤링 호라이즌이 최적의 **1/20만 달성**했습니다.
일반적으로 이 비율에는 **이론적 상한이 없습니다** (임의로 나빠질 수 있음).

### 7.3 우리 시뮬레이션에서 실제로 발생했다

`log4.txt`에서 이 현상이 그대로 관찰됩니다:

```
[T=5~200] 조기 위협들에 탄약을 모두 소진
    ↓
[T=360] [WARN] No operational systems (Total ammo: 0)
[T=365] INTERCEPT FAILED: T98 → A18 - No assignment
[T=370] INTERCEPT FAILED: T99 → A19 - No assignment
[T=375] INTERCEPT FAILED: T100 → A20 - No assignment
```

이것이 롤링 호라이즌 근시안성(myopia)의 **직접적 증거**입니다.

## 8. 벨만 방정식과 차원의 저주

### 8.1 "상태(State)"란?

**정의:** 시간 $t$에서 시스템을 완전히 기술하는 정보.

$$s^t = \Big(\underbrace{\{M_i^t\}_{i \in \mathcal{B}}}_{\text{각 포대의 잔여 탄약}},\ \underbrace{\mathcal{T}^t}_{\text{활성 위협 목록}},\ \underbrace{\text{각 위협의 위치/속도}}_{\text{위협 상태}}\Big)$$

### 8.2 "가치 함수(Value Function)"란?

**정의:** 현재 상태 $s^t$에서 **앞으로 최적으로 행동했을 때** 얻을 수 있는 총 이득.

$$V^t(s^t) = \max_{x^t} \Big[ \underbrace{r(s^t, x^t)}_{\text{지금 이득}} + \underbrace{V^{t+1}(f(s^t, x^t))}_{\text{앞으로의 이득}} \Big]$$

### 8.3 벨만 최적 방정식 (Bellman Optimality Equation)

**쉬운 설명:** "지금 이득 + 앞으로의 이득"을 최대화하는 결정을 찾는 방정식입니다.

$$V^t(s^t) = \max_{x^t \in \mathcal{X}(s^t)} \Big[ \underbrace{r(s^t, x^t)}_{\text{현재 윈도우 이득}} + \underbrace{V^{t+1}(f(s^t, x^t))}_{\text{미래 가치}} \Big]$$

| 항 | 설명 |
|----|------|
| $r(s^t, x^t)$ | 지금 결정 $x^t$을 했을 때 즉시 얻는 이득 |
| $f(s^t, x^t)$ | 지금 결정 후 다음 상태 (탄약 감소, 위협 제거 등) |
| $V^{t+1}(\cdot)$ | 다음 상태에서 앞으로 최적으로 행동했을 때의 이득 |

**롤링 호라이즌 = 미래 가치를 0으로 가정한 것:**

$$\text{롤링 호라이즌이 푸는 것: } \max_{x^t} r(s^t, x^t)$$

$$\text{진짜 최적은: } \max_{x^t} \Big[ r(s^t, x^t) + V^{t+1}(f(s^t, x^t)) \Big]$$

롤링 호라이즌은 $V^{t+1}(\cdot) \equiv 0$으로 근사합니다 — 즉, **"미래는 없다"고 가정**합니다.

### 8.4 차원의 저주 (Curse of Dimensionality)

**왜 정확한 $V^t$를 계산할 수 없는가?**

벨만 방정식을 정확히 풀려면 모든 가능한 상태 $s^t$에 대해 $V^t$를 계산해야 합니다.

**우리 시스템의 상태 공간 크기:**

$$|\mathcal{S}| = \underbrace{\prod_{i \in \mathcal{B}} (M_i + 1)}_{\text{탄약 상태}} \times \underbrace{2^{|\mathcal{T}_{\max}|}}_{\text{위협 활성/비활성}}$$

STRESS_100 시나리오 기준으로 계산하면:

| 요소 | 크기 | 계산 |
|------|------|------|
| LSAM 3개 탄약 (각 24발) | $(25)^3$ | $\approx 1.6 \times 10^4$ |
| MSAM 3개 탄약 (각 48발) | $(49)^3$ | $\approx 1.2 \times 10^5$ |
| 위협 100개 활성/비활성 | $2^{100}$ | $\approx 10^{30}$ |
| **합계** | **$\approx 10^{39}$** | **사실상 계산 불가** |

우주의 원자 수가 약 $10^{80}$개입니다.
$10^{39}$개의 상태를 저장하는 것조차 불가능합니다.

> 이것이 **차원의 저주**입니다: 변수가 늘어날수록 상태 공간이 **지수적으로** 폭발합니다.

### 8.5 근사비의 이론적 하한

**명제:** 롤링 호라이즌의 근사비는 최악의 경우 이론적 상한이 없다.

**증명 스케치:**

포대 1개, 살보 1회, 위협 $N$개가 순서대로 도착:

$$v_k = \begin{cases} \epsilon \quad (k < N) \\ 1 \quad (k = N) \end{cases}$$

롤링 호라이즌: $t=1$에서 $v_1 = \epsilon > 0$이므로 교전 → 탄약 소진.
전체 지평선 최적: 위협 $N$ (가치 1)만 교전.

$$\rho = \frac{1}{N\epsilon} \xrightarrow{\epsilon \to 0} \infty$$

**결론:** $\epsilon$을 0에 가깝게 만들면 근사비가 무한히 커집니다. **∎**

## 9. 최종 결론 요약

### 두 줄 요약

> **단일 윈도우:** 총 단모듈성(TU)에 의해 LP = 정수해 → **전역 최적 보장**
> **전체 시간:** 탄약 연결(coupling) 무시 → **이론적 보장 없음, 임의로 나빠질 수 있음**

### 상세 요약표

| 분석 대상 | 결론 | 근거 |
|-----------|------|------|
| 단일 윈도우 내 최적성 | ✅ 전역 최적 (이론 보장) | 제약 행렬 $A'$의 TU 성질 |
| LP 완화 = 정수해 | ✅ 항상 성립 | Hoffman-Kruskal 정리 |
| Branch & Bound 필요성 | ⬛ 이론상 불필요 | LP만으로 정수해 달성 |
| `gapRel=0.01` 역할 | ⬛ 형식적 필요, 실질 gap ≈ 0 | $k_{\text{var}}$가 상한으로 수렴 |
| 전체 시간 축 최적성 | ❌ 보장 없음 | 탄약 coupling 무시 |
| 왜 전체 최적화 불가 | ❌ 상태 공간 $\approx 10^{39}$ | 차원의 저주 |

### 논문 기술 제안

> 본 알고리즘의 단일 최적화 윈도우는 네트워크 흐름 구조를 가지므로, 제약 행렬의 총 단모듈성(TU)에 의해 LP 완화의 최적해가 정수임이 보장된다 (Hoffman-Kruskal, 1956). K-인자의 불확실성 모델링을 위해 McCormick 선형화를 적용하나, solver는 K-인자를 실질적으로 상한값으로 수렴시키므로 TU 성질이 유지된다. 따라서 각 윈도우 내에서는 사실상 전역 최적해를 달성한다.
>
> 그러나 롤링 호라이즌 분해는 벨만 방정식의 미래 가치 함수 $V^{t+1}$을 0으로 근사하는 것과 동치이며, 이로 인한 시간축 준최적성은 최악의 경우 임의로 커질 수 있다 ($\rho \to \infty$). 전체 지평선 최적화는 상태 공간이 $O(10^{39})$에 달하는 차원의 저주로 인해 실시간 교전 환경에서 계산 불가능하며, 롤링 호라이즌은 이에 대한 실용적인 근사 방법이다.
